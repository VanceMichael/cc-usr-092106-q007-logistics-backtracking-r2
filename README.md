# 跨省物流倒查协作

整理跨省倒查药品物流所需的运单、包裹和授权信息。

## 领域资料

仓库中的 `contracts/context.schema.json` 描述基础资料格式，`fixtures/context.json` 给出可公开使用的示例。代码库只负责读取、校验与分析这些资料，业务服务可沿用相同标识和版本约定。

完整的虚构倒查案卷见 `fixtures/case-007.json`（药品归集 → 跨省 → 拆分 → 外省合并 → 部分签收/拒收/转寄全链路，全部为虚构数据）。

当前资料反映的事实包括：

- 案件链条包含跨省物流
- 药品经仓库归集后通过快递外运
- 物流信息用于逐步还原犯罪链条

## 领域模型（`src/logistics/`）

| 模块 | 职责 |
| --- | --- |
| `events.py` | 运单 append-only 事件流；`registered/correction/cancelled/forwarded/rejected/signed/partially_signed/scan/vehicle_batch/packed/unpacked/merged/query_receipt`。承运方晚到更正只能追加 `correction`，原值在 `field_versions()` 中永久保留；`waybill_status()` 折叠出当前状态，注销/转寄/拒收/部分签收均不删除原轨迹。 |
| `entities.py` / `casefile.py` | 主体、脱敏联系方式、地址代号、网点、车次、货物件、箱盒、网售发货记录、调取授权；案卷加载做结构、序号、时间单调与引用完整性校验。 |
| `associations.py` | **只提出候选关联**。同手机号、同地址代号、同昵称、同箱、同车次生成带权重与出处的 `CandidateLink`，状态为 `pending / accepted_lead / ruled_out`，由侦查员逐条决定；包内刻意不提供任何“合并/认定同一主体”的接口。同一张运单的寄收双方不互为候选（正常交易不互相牵连）；面单寄件地与实际揽收网点不一致只作为观察项。 |
| `freezes.py` | 材料冻结登记，按材料指纹（运单底单/网点扫描流水/车次清单/查询回执）跨小组去重；重复冻结抛 `FreezeConflict` 并指出先持有小组。冻结前强制校验授权：须存在、未撤销、未过期，且承运方与运单/网点范围覆盖；无“全量授权”，范围必须显式列明。 |
| `replay.py` | 从某次网售发货记录出发重放货物归集、跨省、拆分、外省合并与签收/拒收/转寄（含转寄链），给出每件货物的阶段时间线与终态，并列出仍缺失的节点或授权：缺扫描、跨省缺到达省扫描、缺/不符重量、晚到更正缺查询回执、授权缺口、转寄断点、去向不明的件。 |

标识与版本约定：

- 所有 id 由案卷资料给定，加载器校验引用完整性，不允许悬空引用（转寄目标未到卷除外，由重放作为缺口报告）。
- 字段值只有“版本”概念：`registered` 为第一版，每次 `correction` 追加一版；任何分析都基于最新版本，但所有旧版本可审计。
- 地址、手机号分别以代号和脱敏值保存，资料中不含明文个人信息或凭据。

## 本地校验

```
pip install -r requirements.txt
python -m pytest
```

所有示例均为虚构数据，不含真实个人信息、账号或访问凭据。
